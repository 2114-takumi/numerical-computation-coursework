## コードの処理と補足説明

### 3.1 二分法：手順と数式の対応

1. `scanf` で区間端点 `a`、`b` を読み、確認入力 `z` が `'y'`、`a < b`、`FNF(a) * FNF(b) < 0` の条件を満たすまで入力を繰り返す。
2. `k = 0` として、`while(b - a > 0.000001)` で区間を縮小する。各回の最初に回数と更新前の区間を表示する。
3. `c = (a + b) / 2.0` で中点を計算する。
4. `FNF(a) * FNF(c) > 0` なら `a = c`、それ以外なら `b = c` とし、符号の異なる両端を持つ区間を残す。
5. 10回ごとに表示継続を入力で確認する。中断せずループを抜けた場合は、最終区間の中点 `(a + b) / 2.0` を表示する。

原理の中点式 `c = (a + b)/2` と符号判定が、そのまま中点計算と `if` 文に対応する。区間幅は更新ごとに半分になるため、初期区間幅を `b₀ − a₀` とすると、`n` 回更新後の幅は `(b₀ − a₀)/2ⁿ` となる。

コードの継続条件は厳密には `b − a > 10⁻⁶` であり、幅がちょうど `10⁻⁶` でも終了する。PDF本文の終了条件は `b − a < 10⁻⁶` と記載されている。今回の初期区間 `[0, 1]` では等号は生じず、この違いは掲載結果に影響しない。

### 3.2 ニュートン法：手順と数式の対応

1. 初期近似値 `x` を入力し、`k = 1` として最初の行を表示する。
2. `k` を1増やし、`xn = x - FNF(x) / FNG(x)` で次の近似値を計算する。
3. `xn` と符号付きの差 `xn - x` を表示する。
4. `fabs(xn - x) < 0.000001` ならループを終了する。
5. 終了しなければ `x = xn` とし、10行ごとの継続確認を挟みながら繰り返す。

マクロ `FNF(x)` は `f(x) = cos(x) − x`、`FNG(x)` は導関数 `f′(x) = −sin(x) − 1` に対応する。したがって更新式は

$$
x_{n+1}=x_n-\frac{\cos(x_n)-x_n}{-\sin(x_n)-1}
$$

となる。収束判定に使うのは残差 `|f(x)|` ではなく、連続する近似値の差の絶対値である。

PDFは「5回目の反復」と記述するが、コードの回数 `k` は初期値を1として数えている。表の5行には初期値1行と更新4回が含まれ、ニュートンの更新式を評価する回数は4回である。

## 確認状況と注意点

### 原本にある問題点

両方のソースに、`\計算過程`、`\収束値` など、バックスラッシュの直後に日本語が続く文字列がある。二分法には `\正しく入力しましたか？n(y/n)`、ニュートン法には `\表示を継続しますかn?` と `\表示を終わりますn.` もある。これらは通常の改行指定 `\n` とは異なる。コンパイラによる診断や出力への影響が考えられるが、この環境ではCのコンパイル結果を確認できていないため、特定の診断・出力を実測したものとしては記録しない。

ニュートン法の `z` は初期化されておらず、値の代入は10行ごとの継続確認でしか行われない。掲載条件で5行目に収束すると、それ以前に `z` へ代入する経路を通らず、最後の `if(z != 'n')` で未初期化の値を参照する。数値計算の式が掲載表と一致しても、復元したCプログラムが最終メッセージを安定して表示することは確認できない。

両プログラムとも `scanf` の戻り値を確認していない。またニュートン法には `FNG(x)` が0に近い場合の保護処理や反復回数の上限がない。これらはコードを読んで確認した注意点であり、失敗を起こす入力でのC実行実験は行っていない。

二分法は10回ごとの確認で中断できる。掲載された20行を得るには10回目と20回目で表示継続を選ぶ必要がある。また表1は更新前の区間を小数点以下5桁で表示しているため、19・20行目の幅の `0.00000` は真の区間幅が0であることを意味しない。
